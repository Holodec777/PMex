# Модель данных и нормализация

Схема находится в `database/schema.sql`. Сущности разделены по назначению; повторяющиеся названия ролей, категорий и статусов вынесены в справочники. В `order_items` хранится цена на момент заказа, чтобы последующее изменение цены товара не меняло историю.

| Таблица | Ключи и назначение |
|---|---|
| `roles` | PK `id`, уникальный код роли |
| `users` | PK `id`, уникальный `login`, FK `role_id → roles.id` |
| `categories` | PK `id`, уникальное название категории |
| `products` | PK `id`, FK `category_id → categories.id`, цена, остаток, признаки и путь обложки |
| `customers` | PK `id`, ФИО, телефон, email |
| `order_statuses` | PK `id`, уникальный код и название статуса |
| `orders` | PK `id`, FK на клиента и статус, дата создания, срок доставки |
| `order_items` | PK `id`, FK на заказ и товар, количество, цена-снимок; уникальная пара заказа/товара |

### 3НФ

- **1НФ:** поля содержат одно значение; товары заказа хранятся отдельными строками в `order_items`.
- **2НФ:** ключи таблиц простые; атрибуты строки заказа относятся к её ключу, а не к части составного ключа.
- **3НФ:** ФИО клиента хранится в `customers`, названия категории/статуса/роли — в справочниках. В заказах и товарах остаются только внешние ключи; транзитивные зависимости не дублируются.

Все отношения реализованы внешними ключами с включённым `PRAGMA foreign_keys`. Удаление товара, на который ссылается заказ, запрещено `ON DELETE RESTRICT` и проверкой интерфейса. Индексы добавлены для названия, категории, срока доставки и ссылок из строк заказа.
